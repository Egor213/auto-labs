# md2docx

Конвертер Markdown в DOCX.

Берёт `.md` файл со специальной разметкой и генерирует `.docx`:
титульный лист по шаблону кафедры, правильные поля, шрифты,
отступы, нумерация страниц, редактируемые формулы Word (OMML),
таблицы, рисунки, листинги кода.

### Требования

- Python 3.9 или новее
- pip

### Шаги

```bash
# 1. Клонировать/скопировать проект и перейти в него
cd auto-labs

# 2. Создать виртуальное окружение (рекомендуется)
python -m venv venv

venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

### Что установится

| Пакет          | Зачем |
|----------------|-------|
| `python-docx`  | Создание и редактирование DOCX |

| `math2docx`    | Вставка формул как нативных объектов Word (OMML) |

## Формат Markdown-файла

### Frontmatter

Начинайте файл с YAML-блока между `---`. Все поля необязательные —
значения по умолчанию берутся из `src/template.yaml`.

```yaml
---
department: test
discipline: Базы данных
lab_number: 4
topic: Нагрузочное тестирование БД
student: test
group: 1234
teacher: test
city: Санкт-Петербург
year: 2024
template_docx: ""        # путь к своему титульнику (опционально)
---
```

| Поле            | Обязательно | Что это |
|-----------------|-------------|---------|
| `university`    | нет         | Полное название вуза (многострочно через `\|`) |
| `department`    | нет         | Название кафедры |
| `discipline`    | **да**      | Название дисциплины в кавычках-ёлочках |
| `lab_number`    | **да**      | Номер лабораторной |
| `topic`         | **да**      | Тема работы |
| `student`       | **да**      | ФИО студента |
| `group`         | **да**      | Номер группы |
| `teacher`       | **да**      | ФИО преподавателя |
| `city`          | нет         | Город (по умолчанию Санкт-Петербург) |
| `year`          | нет         | Год |
| `template_docx` | нет         | Путь к пользовательскому `.docx`-титульнику |

**Важно.** Внутри YAML строки в двойных кавычках нужно экранировать (`\"`),
либо использовать одинарные кавычки или `|` (literal block scalar).

### Заголовки

Три уровня. Дальше — не поддерживается.

| Синтаксис                | Стиль Word  | Где использовать |
|--------------------------|-------------|------------------|
| `# ПРИЛОЖЕНИЕ А`         | Заголовок 1 | Приложения (капс, по центру) |
| `## Цель работы`         | Заголовок 2 | Основные разделы отчёта |
| `### Подраздел`          | Заголовок 3 | Вложенные подразделы |

**Правила оформления:**
- Основные разделы (Цель, Задание, Выполнение, Выводы) — всегда `##`.
- Приложения — всегда `#`, слово `ПРИЛОЖЕНИЕ` пишите капсом.
- После номера ставьте пробел: `# ПРИЛОЖЕНИЕ А`, а не `# ПРИЛОЖЕНИЕА`.

Пример:

```markdown
## Цель работы

Текст цели.

## Задание

Вариант 7.

### Подзадача

Текст подзадачи.

# ПРИЛОЖЕНИЕ А

Исходный код.
```

### Абзацы

**Главное правило:** пустая строка = новый абзац Word.

Подряд идущие непустые строки **склеиваются в один абзац**, а переносы
внутри блока становятся мягкими (`<w:br/>`, Shift+Enter в Word).
Это позволяет удобно разбивать длинные абзацы в `.md` без риска
получить «рваный» текст в Word.

```markdown
Это один абзац.
Он продолжается на новой строке в md,
но в Word это будет единый абзац с мягкими переносами.

А это уже второй абзац.
```

**Правила оформления:**
- Не делайте пустую строку внутри одного смыслового абзаца — она
  разрежет его на два.
- Не начинайте обычную строку с `#`, `-`, `1.`, `![`, `|`, `` ``` ``,
  `$$` — иначе строка будет распознана как спец-элемент.
- Не оставляйте двойных пустых строк — они не дают лишних пробелов,
  но захламляют исходник.

### Списки

Используйте обычный Markdown-синтаксис.

**Маркированный:**
```markdown
- создание баз данных;
- чтение и вставка данных;
- удаление данных.
```
Отрендерится как список с маркером `–` (en-dash) и висячим отступом.

**Нумерованный:**
```markdown
1. Написать скрипт, заполняющий БД.
2. Измерить время выполнения запросов.
3. Добавить индексы.
```
Номера расставляет сам конвертер, поэтому неважно, какие цифры вы
написали (`1.`, `5.`, `99.`) — в Word они пойдут по порядку 1, 2, 3...

**Правила оформления:**
- Между пунктами пустую строку не ставьте — иначе каждый пункт
  начнёт новый список и нумерация сбросится.
- Внутри пункта можно использовать инлайн-разметку.
- Не смешивайте `-` и `*` в одном списке без необходимости.
- Вложенные списки не поддерживаются — используйте `###`-подразделы.

Правильно:
```markdown
1. Первый пункт.
2. Второй пункт.
3. Третий пункт.
```

Неправильно:
```markdown
1. Первый пункт.

2. Второй пункт.   <!-- разорвёт список -->

3. Третий пункт.
```

### Инлайн-разметка

| Синтаксис          | Результат |
|--------------------|-----------|
| `**жирный**`       | **жирный** |
| `__жирный__`       | **жирный** |
| `*курсив*`         | *курсив* |
| `` `код` ``        | `Courier New 12` |
| `[текст](URL)`     | гиперссылка |
| `t_{i}`            | нижний индекс: t<sub>i</sub> |
| `x^{2}`            | верхний индекс: x<sup>2</sup> |

**Правила оформления:**
- `**жирный**` без пробелов внутри звёздочек: `** текст **` не сработает.
- Ссылки всегда с полным URL, включая `https://`.
- `_{...}` и `^{...}` — фигурные скобки **обязательны**:
  `t_i` не сработает, `t_{i}` — да.
- Не используйте одновременно `*` и `_` для одного и того же.

### Типографика

Символ `--` автоматически превращается в `–` (en-dash), `---` в `—`
(em-dash). Это требование кафедры: длинные тире в исходнике заменяются
на короткие при рендере.

| В `.md`      | В `.docx` |
|--------------|-----------|
| `--`         | `–`       |
| `---`        | `—`       |

**Правила оформления:**
- В обычном тексте пишите `--`, не `—` и не `–`. Это позволит
  избежать проблем с кодировкой и упростит диффы.
- Внутри `` `кода` `` и внутри URL замены **не происходит** — можно
  спокойно использовать `--help` и `https://example.com/a--b`.
- В подписях к таблицам/рисункам/листингам тоже используйте `--`:
  `Таблица 1 -- Время выполнения`.

### Формулы

Обёртка `$$ ... $$` — выключная формула (отдельным абзацем по центру).

```markdown
$$ \bar{t} = (1/n) * sum(t_{i}) $$
```

Или многострочно:

```markdown
$$
\bar{t} = \frac{1}{n} \sum_{i=1}^{n} t_i
$$
```

Формулы парсятся через `math2docx` и вставляются как **нативные объекты
Word** — их можно редактировать, кликнув в Word (появится вкладка
«Конструктор формул»).

**Поддерживаемый синтаксис LaTeX** (наиболее часто нужное):

| LaTeX                       | Значение |
|-----------------------------|----------|
| `\frac{a}{b}`               | дробь a/b |
| `\sqrt{x}`                  | корень |
| `x^{2}`, `x_i`              | степень / индекс |
| `\sum_{i=1}^{n}`            | сумма |
| `\int_{a}^{b}`              | интеграл |
| `\alpha \beta \gamma`       | греческие буквы |
| `\cdot \times`              | умножение |
| `\leq \geq \neq \approx`    | сравнения |
| `\bar{x}`                   | черта сверху |
| `\hat{x}`, `\vec{x}`        | крышка / вектор |
| `\left( ... \right)`        | автоматические скобки |

**Правила оформления:**
- Формулу всегда выделяйте в отдельный блок (даже если короткая).
- Ставьте пробелы вокруг `=` и бинарных операторов.
- Если формула «не собирается», конвертер напишет `[WARN]` и вставит
  её как текст — проверьте синтаксис LaTeX.
- Нумерацию формул (как `(1)`) конвертер не делает. Если нужно —
  пишите номер прямо в тексте формулы: `$$ E = mc^2 \quad (1) $$`.

### Рисунки

```markdown
![Рисунок 1 -- Структура базы данных](images/structure.png)
```

Обязательно:
- путь к файлу — **относительный**, относительно `.md`;
- подпись начинается со слова `Рисунок N --`;
- первая часть — `Рисунок` (не `рис.`, не `Рис.`);
- между номером и текстом — `--`, а не `–` или `-`.

Конвертер:
1. ставит картинку по центру;
2. подпись — снизу, по центру, 14 пт;
3. автоматически масштабирует широкие картинки до 16 см.

**Правила оформления:**
- Сначала в тексте — **ссылка** на рисунок, потом сам рисунок:
  `см. рисунок 1` → `![Рисунок 1 -- ...](...)`.
- Нумерация — вручную, сквозная по документу.
- Имя файла — латиницей, без пробелов: `structure.png`,
  `time_plot.png`. Не `схема бд.png`.
- Если файл не найден — в консоль попадёт `[WARN]`, в документе
  останется только подпись. Проверяйте пути.

Правильно:
```markdown
Структура базы данных приведена на рисунке 1.

![Рисунок 1 -- Структура базы данных](images/structure.png)
```

### Таблицы

Таблица **обязательно** должна иметь подпись **над собой**:

```markdown
Таблица 1 -- Время выполнения запросов

| Количество записей | task1 (сек) | task2 (сек) |
|-------------------:|------------:|------------:|
| 100                | 0.006       | 0.008       |
| 1 000              | 0.005       | 0.007       |
| 10 000             | 0.007       | 0.010       |
```

**Правила оформления:**
- Строка подписи идёт **сразу перед** таблицей (без пустой строки).
- Подпись начинается с `Таблица N --`, где `N` — сквозной номер.
- Выравнивание столбцов в шапке — двоеточия в строке-разделителе:
  - `|:---|` — по левому краю,
  - `|:--:|` — по центру,
  - `|---:|` — по правому краю (удобно для чисел).
- Числа — выравнивайте по правому краю.
- Если строк больше 5 — конвертер автоматически уменьшит шрифт
  до 12 пт (по требованиям кафедры).
- Первая строка после подписи — всегда **шапка**. Она станет полужирной.
- В тексте таблицу предваряйте ссылкой: «в таблице 1 приведены...».

### Листинги

Блоки кода тройными обратными кавычками. Язык после ```` ``` ````
можно опустить, но лучше указывать — для подсветки.

**Без подписи:**
````markdown
```python
def hello():
    print("Hello")
```
````

**С подписью через двоеточие:**
````markdown
```python: Листинг 1 -- Функция приветствия
def hello():
    print("Hello")
```
````

**Или подпись строкой выше:**
````markdown
Листинг 1 -- Функция приветствия

```python
def hello():
    print("Hello")
```
````

**Правила оформления:**
- Подпись начинается с `Листинг N --`.
- Шрифт — Courier New 11, одинарный интервал, без отступа
  первой строки (по требованиям кафедры).
- В листинге можно использовать `--` без преобразования в en-dash
  (типографика в код не применяется).
- Основной код обычно выносят в `# ПРИЛОЖЕНИЕ А`, а в тексте
  приводят только ключевые фрагменты (не более ~5 строк за раз,
  согласно методичке).

### Приложения

Приложение — это заголовок **первого уровня**:

```markdown
# ПРИЛОЖЕНИЕ А

Полный исходный код.

```python: Листинг 1 -- Модуль db.py
...
```
```

**Правила оформления:**
- Заголовок всегда капсом: `ПРИЛОЖЕНИЕ А`, `ПРИЛОЖЕНИЕ Б` и т. д.
- Для дополнительных приложений используйте русские буквы:
  А, Б, В, Г...
- Начинайте каждое приложение с новой страницы. В текущей версии
  конвертера это делается через ручную вставку пустого `#`-
  заголовка или добавление разрыва в Word (автоматический разрыв
  можно добавить по запросу).

## Пользовательский титульный лист

Если стандартный (встроенный) титульник не подходит — можно
подставить свой `.docx` с плейсхолдерами.

### Как подготовить шаблон

1. Откройте официальный титульник (`.doc` из методички) в Word.
2. **Файл → Сохранить как → `title.docx`** (обязательно `.docx`,
   иначе `python-docx` его не прочитает).
3. Замените значения на плейсхолдеры:

```
Кафедра {{ department }}

ОТЧЕТ
по лабораторной работе № {{ lab_number }}
по дисциплине «{{ discipline }}»
Тема: {{ topic }}

Студент(ка) гр. {{ group }}              Преподаватель
{{ student }}                            {{ teacher }}

Санкт-Петербург
{{ year }}
```

### Доступные плейсхолдеры

`ministry`, `university`, `department`, `lab_number`, `discipline`,
`topic`, `student`, `group`, `teacher`, `city`, `year`.

### Как подключить

В `.md` в frontmatter добавьте:

```yaml
template_docx: title.docx
```

Путь — относительно `.md` файла.

### Что происходит дальше

- Конвертер загрузит `title.docx`, подставит значения и использует
  его как первую страницу.
- **Независимо от источника титульника** применит поля, стили
  и нумерацию страниц к остальному документу.
- Если `title.docx` не найден — использует встроенный титульник
  и напишет `[WARN]`.

## Что делать, если что-то пошло не так

### `KeyError: "no style with name 'Listing'"`

Старая версия. Обновите `src/elements.py` — в актуальной версии все
стили создаются автоматически через `_get_or_create_paragraph_style`.

### `[WARN] Изображение не найдено: ...`

Файл картинки не найден. Проверьте:
- путь в `.md` указан относительно `.md` (не относительно корня проекта);
- имя файла — точно такое, включая регистр (в Linux это критично);
- нет русских букв и пробелов в имени (лучше переименовать латиницей).

### `[WARN] Не удалось вставить формулу '...'`

LaTeX-синтаксис не распарсился. Проверьте:
- закрыты ли фигурные скобки;
- нет ли лишних `$` внутри формулы;
- установлен ли `math2docx` (`pip install math2docx`).

### `add_math() got an unexpected keyword argument 'inline'`

Старая версия `src/formula.py`. Обновите файл — там больше нет
вызова с `inline=`.

### Пустая нумерация в списке

Скорее всего, между пунктами стоит пустая строка. Уберите её —
список должен идти сплошняком.

### Список «разъезжается» на несколько колонок

Слишком большой левый отступ. По умолчанию 0,75 см — этого
достаточно. Если хотите изменить — правьте `indent_cm` в вызове
`add_list_item` в `src/parser.py`.

### Формулы выглядят как текст

Проверьте, установлен ли `math2docx`:

```bash
pip install math2docx
python -c "import math2docx; print(math2docx.__version__)"
```

Если нет — конвертер напишет `[WARN] math2docx не установлен`.

### `template_docx не найден`

Убедитесь, что `title.docx` лежит рядом с `.md` или укажите
абсолютный путь в `template_docx`.
